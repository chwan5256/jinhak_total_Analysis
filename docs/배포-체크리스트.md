# 배포 체크리스트 (GitHub Desktop · Windows)

## 최초 1회

- [ ] PowerShell에서 `.github\workflows\deploy.yml` 배치 (아래 명령)
- [ ] GitHub Desktop → File → Add local repository → `C:\repos\jinhak_total_analysis`
- [ ] 빨간 문장 안의 파란 링크 **create a repository** 클릭 (아래 회색 버튼 아님)
- [ ] Create a Repository 창에서 **README 체크 해제 / Git ignore None / License None**
- [ ] Commit to main
- [ ] Publish repository → **Keep this code private 체크 해제**
- [ ] GitHub 웹 → Settings → Pages → Source를 **GitHub Actions**로 변경
- [ ] Actions 탭이 초록 체크인지 확인

```powershell
cd C:\repos\jinhak_total_analysis
New-Item -ItemType Directory -Force .github\workflows | Out-Null
Move-Item _setup\deploy.yml .github\workflows\deploy.yml -Force
Remove-Item _setup -Force
```

> README와 .gitignore를 반드시 None으로 두는 이유: 두 파일이 이미 저장소에 있고,
> `.gitignore`는 `*.pdf` / `생기부*` / `학생부*` 를 차단하는 개인정보 안전장치다.
> 템플릿으로 덮이면 학생 생기부 PDF가 실수로 커밋될 수 있다.

## 수정할 때마다

```powershell
cd C:\repos\jinhak_total_analysis
.\scripts\release.ps1 "무엇을 바꿨는지 한 줄"        # 패치 (2026.4 -> 2026.5)
.\scripts\release.ps1 "큰 개편"           -Minor    # 마이너 (2026.4 -> 2027.0)
.\scripts\release.ps1 "오타"              -NoBump   # 버전 유지
```

또는 GitHub Desktop에서 Commit to main → Push origin.

처음 한 번 실행 정책이 막으면:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

## 배포 전 자동 검사 3가지

`main`에 푸시되면 GitHub Actions가 아래를 순서대로 확인하고, 하나라도 실패하면 배포하지 않는다.

| 검사 | 실패 조건 |
|---|---|
| 인라인 스크립트 문법 | `node --check`가 통과하지 못하는 JS |
| 단일 파일 원칙 | `index.html`이 로컬 `.js` / `.css`를 참조하기 시작하면 |
| 버전 표기 일치 | `const VERSION`과 `<title>`의 버전이 다르면 |

## 막혔을 때

| 증상 | 해결 |
|---|---|
| `Add repository` 버튼이 회색 | 정상. 빨간 문장 안의 파란 `create a repository` 링크를 누른다 |
| Changes에 파일이 안 보임 | `_setup` 이동을 안 했거나 다른 폴더를 물렸다. 상단 Current repository 확인 |
| Actions 빨간 X | 로그에서 위 3검사 중 어느 단계인지 확인 |
| Pages 404 | Source가 `GitHub Actions`인지 확인. 첫 배포는 최대 5분 |

## 절대 커밋하지 않을 것

- 학생 개인정보가 담긴 생기부 PDF·한글 파일 (`.gitignore`가 1차로 막지만 최종 확인은 사람이 한다)
- 평가 문항·정답·채점기준표 — 정적 사이트에는 서버가 없어 접근 통제를 걸 수 없다
- `desktop.ini` 등 Windows·구글드라이브 잡파일
